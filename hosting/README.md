# ESCAPE на REG.RU Host-0

Домен: **escapeworkspaceru.ru** (обратите внимание на `ru` перед точкой).

Для текущего MySQL-сайта: **фотографии для су-шефа и архив с календарём** — [PHOTO_ARCHIVE_UPDATE.md](PHOTO_ARCHIVE_UPDATE.md), архив `hosting/photo-archive-update.zip`. Инструкция содержит загрузку, установку, проверку и откат.

Текущий статус: PHP-версия собрана; локальные проверки backend и браузерных сценариев пройдены. Загрузка на хостинг выполняется только после просмотра пользователем.

## Что изменилось

React-интерфейс и компоненты остаются общими с исходным приложением. Отдельная сборка браузера использует PHP API вместо Next.js server components. Вход и все изменения идут через PHP к подписанному Google API. Сессии по-прежнему хранятся в Google Sheets: браузер получает только HttpOnly/SameSite cookie с непрозрачным токеном. PHP-сессии не нужны.

Google проверяет роль и доступ к каждой задаче, фотографии и операции. Сохранены четыре роли, управление аккаунтами и удаление с сохранением истории, индивидуальные задачи, каталог дополнительных типов, общие выполнения, активность только поваров, статистика. Новые пароли хешируются scrypt в Apps Script; старые scrypt-хеши не меняются.

Секреты читаются из переменных окружения либо приватного `.env` вне `www`. Публичная сборка их не содержит. Node.js нужен только на компьютере разработчика для сборки, на Host-0 не нужен.

## Локальная сборка и тест

```sh
npm run build:hosting
npm run test:hosting
```

Для PHP-тестов нужен PHP 8.3+ с cURL/GD; путь можно задать через `ESCAPE_PHP_BIN`. Автотест использует только отдельную память и фиктивные аккаунты. Никогда не обращается к рабочей Google-таблице.

```sh
npm run preview:hosting
```

Просмотр: http://localhost:3102. Единственный исходный аккаунт берётся из локальных `BOOTSTRAP_SOUS_CHEF_*`; в тестовой базе хранится только хеш пароля. Изменения теста исчезают при остановке процесса. Никакие облачные данные не изменяются.

## Порядок публикации после просмотра

1. В Google Apps Script заменить содержимое `Код.gs` файлом `google/dist/Code.js` из текущей сборки. Сохранить. Через управление развёртываниями обновить существующее Web App на новую версию, сохранив URL. **setupDatabase, bootstrap и сброс таблицы запускать не нужно.** Это обновление добавляет создание/смену паролей через PHP, без изменения схемы и данных.
2. Проверить валидный SSL для escapeworkspaceru.ru. Включить PHP 8.3, cURL и GD с WebP (GD нужен для JPEG fallback). На хостинге уже проверены PHP 8.3.31, cURL, GET к Google, post_max_size 256M, upload_max_filesize 256M, max_execution_time 300. Подписанные POST и фотографии окончательно проверяются после установки.
3. В каталоге пользователя создать **escape-private рядом с www**, не внутри него. Скопировать туда содержимое `hosting/dist/escape-private`: `gateway.php`, `config.php`, `.env.example`.
4. Подготовить приватные переменные: `npm run prepare:hosting-env`. Созданный файл `hosting/private-upload/.env` загрузить **только в escape-private/.env**. Он содержит Google URL, HMAC-секрет, cron-секрет и origin; пароль первоначального пользователя не включён. Права файла 600, каталога 700. Не отправлять его в чат, Git или общедоступный архив.
5. Содержимое `hosting/dist/www` (включая скрытый `.htaccess`) загрузить в `www/escapeworkspaceru.ru`. Не загружать исходники, node_modules или корневой `.env` в www. `.htaccess` включает HTTPS и маршрутизацию API/страниц.
6. Проверить вход существующего Артема, все роли, создание/смену пароля тестового аккаунта, выполнение с фото, просмотр фото, выход. Удалить созданные тестовые аккаунты через интерфейс. Перед этим согласовать тестовые изменения рабочей базы.

Ожидаемая структура:

```text
data/
  escape-private/
    gateway.php
    config.php
    .env
  www/
    escapeworkspaceru.ru/
      .htaccess
      index.html
      api.php
      assets/
      images/
```

`api.php` ожидает именно такое расположение приватного каталога. Если структура хостинга отличается, нужно изменить единственный путь подключения в api.php. Приватные файлы не должны становиться доступны по HTTP.

## Фиксация статистики

Обновление действующего MySQL-сайта на рабочий день с 04:00: [инструкция и состав архива](WORKDAY_UPDATE.md).

Для MySQL используйте CRON ispmanager: приватный `snapshot.php` выбирает backend из `DB_BACKEND` и фиксирует итоги в MySQL. Триггер Apps Script не фиксирует данные MySQL. Расписание — `0 4 * * *` в Europe/Moscow (04:00 МСК = 01:00 UTC); часовой пояс планировщика проверить в панели. До 04:00 задания и выполнения остаются в прежнем рабочем дне, после 04:00 доступен новый набор. Пропущенные итоги восстанавливаются при открытии статистики или следующем запуске cron; уже сохранённые итоги не пересчитываются.

Пример команды при стандартном пути пользователя:

```sh
/usr/bin/php /var/www/u3638340/data/escape-private/snapshot.php
```

Путь PHP уточняется в Shell-клиенте (`which php`); использовать PHP 8.3 с cURL. Секретов в команде нет. Также сохранён POST `/api/cron` с `Authorization: Bearer CRON_SECRET` для существующего внешнего планировщика.

## Ограничения и откат

Производительность и квоты Google не изменились, нагрузочный тест не проводился. Рабочий сайт ещё нужно проверить на Host-0. Не кэшировать приватные API и фото через CDN. Исходный Next.js запуск остаётся доступен; обновлённый Google backend совместим с ним. Для отката PHP-релиза восстановить предыдущие публичные и приватные файлы, таблицы не сбрасывать.


## Обновление: 1–4 фотографии к заданию

Для действующего сайта на MySQL используйте отдельный архив `hosting/photos-update.zip` и инструкцию [PHOTOS_UPDATE.md](PHOTOS_UPDATE.md). Обновляются `mysql.php`, `gateway.php`, `index.html` и файлы `assets`. Настройки PHP должны разрешать каждый файл до 3 МБ (`upload_max_filesize >= 3M`), запрос минимум 13 МБ (`post_max_size >= 13M`) и не менее 4 файлов (`max_file_uploads >= 4`); на хостинге с лимитами 256 МБ их повышать не требуется. Приложение проверяет максимум 4 файла и общий размер 13 МБ. Схема существующей MySQL подходит без миграции.
