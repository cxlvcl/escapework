# Обновление рабочего дня: 04:00 МСК

Для действующего сайта escapeworkspaceru.ru с `DB_BACKEND=mysql`.

Рабочая дата длится с 04:00 до 03:59:59 следующего календарного дня по Москве. Станционные и холодильные задания, дополнительные назначения и фотографии остаются доступны повару после полуночи. В 04:00 начинается новая рабочая дата, станция повара остаётся выбранной. Открытая страница запрашивает свежие данные на границе дня и при возвращении во вкладку. Недельная активность также считается с понедельника 04:00 МСК.

Статистика «Вчера» больше не зависит только от успешного запуска cron: при открытии отчёта сервер под блокировкой сохраняет недостающие закрытые дни из истории заданий и выполнений. Восстановление ограничено 32 днями и первой известной датой заданий/выполнений. Уже сохранённые итоги не пересчитываются. «Сегодня» и «Вчера» отсчитываются от текущей рабочей даты; например, 14 сентября в 02:00 «Сегодня» — рабочий день 13 сентября.

## Установка на текущий хостинг

Архив: `hosting/workday-update.zip`. Он содержит `escape-private/mysql.php`, `www/index.html`, два файла `www/assets/` и эту инструкцию. Конфигурации, секретов и выгрузки базы в архиве нет.

Установите обновление днём, после 04:00 МСК. Новая граница применяется к дальнейшей работе. Обычная установка и `snapshot.php` не меняют `work_date` уже записанных выполнений: если повара отмечали задания сегодня между 00:00 и 04:00 до обновления, выполните разовый перенос ниже. Иначе эти отметки останутся в сегодняшнем дне, несмотря на новое правило.

1. Сохраните копии текущих `escape-private/mysql.php` и публичного `index.html` в приватный каталог резервной копии. Сохраните текущие файлы `assets` до проверки обновления.
2. Загрузите `escape-private/mysql.php` из архива в `/var/www/u3638340/data/escape-private/mysql.php` с заменой.
3. Загрузите оба файла из `www/assets/` в `/var/www/u3638340/data/www/escapeworkspaceru.ru/assets/`. После этого замените `www/index.html` в `/var/www/u3638340/data/www/escapeworkspaceru.ru/index.html`.
4. В ispmanager измените существующее задание CRON для `snapshot.php`: каждый день, **час 4, минута 0**, часовой пояс Europe/Moscow. Расписание `0 4 * * *`; для планировщика в UTC — `0 1 * * *`. Триггер Apps Script не фиксирует данные MySQL.

Команда CRON:

```sh
/usr/bin/php /var/www/u3638340/data/escape-private/snapshot.php
```

После установки выполните ту же команду один раз в Shell-клиенте. Ответ `success: true` означает, что фиксация прошла успешно. Затем обновите сайт и откройте «Статистика → Вчера», фильтр станции и «Неделя».

Для этого обновления MySQL не требуется повторный импорт, смена `.env`, `config.php`, `gateway.php` или обновление Google Apps Script. Google-мост для старых паролей и фотографий продолжает работать. Сборка `google/dist/Code.js` обновлена для установок, которые по-прежнему используют Google как основную базу; на текущем MySQL-хостинге она не нужна.

## Ночные выполнения, записанные до обновления

Пример перехода: выполненное **13 сентября 2026 в 02:35 МСК** старая версия записала с `work_date=2026-09-13`. По новому правилу оно относится к **12 сентября**. Для таких записей подготовлен отдельный файл `hosting/server/repair-workday.php`. Он не входит в первоначальный `workday-update.zip`; загрузите его рядом с `config.php` в `/var/www/u3638340/data/escape-private/`.

Сначала проверьте конкретную ночь (эта команда не меняет записи):

```sh
/usr/bin/php /var/www/u3638340/data/escape-private/repair-workday.php 2026-09-13
```

В отчёте `completions` — количество переносимых станционных, холодильных и дополнительных выполнений; `duplicateTasks` — количество задач, уже имеющих выполнение за 12 сентября. При `canApply: true` перенесите записи:

```sh
/usr/bin/php /var/www/u3638340/data/escape-private/repair-workday.php 2026-09-13 --apply
```

Скрипт выбирает только записи с исходной рабочей датой 13 сентября и фактическим временем **13 сентября 00:00 ≤ время < 04:00 МСК**. Выполнения после 04:00 и уже правильно датированные записи сохраняют даты. Переносится `work_date`, а идентификаторы, время выполнения, авторы, назначения и ссылки на фото сохраняются. Для станционной задачи, созданной в исходной рабочей дате и уже выполненной ночью, дата создания также переносится: её наличие до 04:00 подтверждается временем выполнения. Незавершённые дополнительные задания не переносятся, поскольку в их данных нет времени создания.

Перед записью создаётся приватный файл `workday-repair-backup-*.json` с исходными изменяемыми строками и итогами двух дат (права 0600). Перенос и пересчёт проходят в одной транзакции под той же блокировкой, что и обычные записи приложения. Это исключение из неизменности готовых итогов: пересчитываются только затронутые даты, закрытые к моменту запуска; текущий рабочий день остаётся незавершённым. Остальная история сохраняется. Повторный запуск после успешного переноса ничего не меняет.

Если за 12 сентября уже есть выполнение той же станционной или холодильной задачи, `canApply` будет `false`; применение остановится без изменения записей. Такие повторы требуют отдельной проверки, чтобы не потерять ни одно фото. После успешного переноса обновите страницу кухни и проверьте «Статистика → Вчера». Сохраните файл резервной копии.

## Проверки разработки

- TypeScript: границы 00:00/03:59:59/04:00, все категории заданий и фото, смена года/месяца, загрузка через границу дня, восстановление пропусков, фильтры, повторная фиксация, срок хранения, заморозка Google.
- PHP 8.3: реальный `MysqlBackend` выполняется с изолированным адаптером SQLite. Проверены SQL-расчёты, даты при разных часовых поясах сервера, откат частично неудавшейся фиксации, права, ночные выполнения и отчёты. Конкуренция InnoDB и рабочая база хостинга этой локальной проверкой не проверялись.
- Разовый перенос старых ночных записей: границы 00:00/04:00, все три категории, сохранение фото и назначений, снятие отметки 02:35 с сегодняшней кухни, пересчёт вчерашних итогов и фильтров станций, приватная резервная копия, остановка при повторах и ошибке копирования, откат при ошибке SQL и повторный запуск. Проверено тем же изолированным адаптером SQLite.
- Мобильные браузерные сценарии PHP-приложения проверяют вход, права, задания, фото, дополнительные задачи, управление аккаунтами и отчёты.

Повторный запуск PHP-проверки: `ESCAPE_PHP_BIN=/путь/к/php node --import tsx --test tests/mysql.test.ts` (PHP 8.3+ с SQLite3). Общие проверки: `npm test`, `npm run typecheck`, `npm run lint`, `npm run build:hosting`, `npm run test:hosting`.
