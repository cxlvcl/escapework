# Обновление: от 1 до 4 фотографий к заданию

Для действующего сайта escapeworkspaceru.ru с `DB_BACKEND=mysql`.

При выполнении задания повар выбирает от одной до четырёх фотографий. Можно выбрать несколько сразу или добавлять по одной, удалить лишнюю миниатюру перед отправкой и подтвердить выполнение. Без фото подтверждение недоступно; после выбора четырёх добавление блокируется. После сохранения все снимки можно просмотреть стрелками в карточке задания; в разделе «Фотографии» видны все миниатюры. Это работает для задач станций, холодильников и дополнительных задач.

Несколько снимков относятся к одному выполнению и дают +1 в статистику. Прежние задания с одним фото продолжают открываться. Рабочий день по-прежнему начинается в 04:00 МСК.

## 1. Загрузить архив

На компьютере откройте папку проекта `EscapeCheckList/hosting` и найдите **`photos-update.zip`**. В ispmanager откройте «Менеджер файлов → escape-private» и загрузите именно этот ZIP-архив.

Полный путь на сервере после загрузки:

```text
/var/www/u3638340/data/escape-private/photos-update.zip
```

В архиве находятся два серверных файла (`mysql.php`, `gateway.php`), `www/index.html`, два файла `www/assets/` и эта инструкция. Секретов, настроек подключения и данных базы в нём нет.

## 2. Установить обновление

Откройте «Shell-клиент», вставьте весь блок и нажмите Enter:

```sh
photos_update=$(mktemp -d /var/www/u3638340/data/escape-private/photos-update-XXXXXX) &&
unzip -q /var/www/u3638340/data/escape-private/photos-update.zip -d "$photos_update" &&
/usr/bin/php -l "$photos_update/escape-private/mysql.php" &&
/usr/bin/php -l "$photos_update/escape-private/gateway.php" &&
cp /var/www/u3638340/data/escape-private/mysql.php "$photos_update/mysql.php.before" &&
cp /var/www/u3638340/data/escape-private/gateway.php "$photos_update/gateway.php.before" &&
cp /var/www/u3638340/data/www/escapeworkspaceru.ru/index.html "$photos_update/index.html.before" &&
install -m 644 "$photos_update"/www/assets/* /var/www/u3638340/data/www/escapeworkspaceru.ru/assets/ &&
chmod 644 "$photos_update/escape-private/mysql.php" "$photos_update/escape-private/gateway.php" "$photos_update/www/index.html" &&
mv -f "$photos_update/escape-private/mysql.php" /var/www/u3638340/data/escape-private/mysql.php &&
mv -f "$photos_update/escape-private/gateway.php" /var/www/u3638340/data/escape-private/gateway.php &&
mv -f "$photos_update/www/index.html" /var/www/u3638340/data/www/escapeworkspaceru.ru/index.html &&
echo "Обновление фотографий установлено. Резервные копии: $photos_update"
```

Ожидаемый результат: две строки `No syntax errors detected` и сообщение «Обновление фотографий установлено». Если появилась ошибка, сохраните её текст; не переходите к проверке сайта до её устранения. Каталог с резервными копиями сохраняйте.

Эта установка не требует импорта или изменения таблиц MySQL. Настроенный CRON на 04:00, `.env`, `config.php`, каталог `photos` и Google-мост продолжают использоваться. Публиковать `google/dist/Code.js` на текущем MySQL-хостинге для этого обновления не требуется.

## 3. Проверить сайт

1. Обновите страницу сайта; если форма осталась прежней, закройте вкладку и откройте сайт заново.
2. Войдите поваром, откройте смену и выберите ещё не выполненную задачу. В окне должна появиться строка **«Фотографии: 0 из 4»**.
3. При реальном выполнении задачи выберите несколько снимков. Проверьте миниатюры и удаление лишнего снимка. После четырёх фото кнопки добавления станут недоступны.
4. Подтвердите выполнение и снова откройте карточку: видны счётчик «Фото 1 из 4» и стрелки просмотра. Откройте это же выполнение под су-шефом или шефом — все снимки должны быть доступны.
5. Откройте прежнюю задачу с одним фото: её снимок должен открываться как раньше.

Если PHP сообщает о размере загрузки, проверьте настройки сайта в панели: `upload_max_filesize` не менее `3M`, `post_max_size` не менее `13M`, `max_file_uploads` не менее `4`. Уже выставленные лимиты 256 МБ подходят. Само приложение ограничивает каждый сжатый снимок 3 МБ, сторону 1600 пикселями и общий запрос 13 МБ.

## Проверки разработки

Проверены лимиты 0/1/4/5 снимков, повреждённый файл в наборе, сохранение порядка, все три категории задач, права каждого снимка, повторная отправка и смена набора после сетевой ошибки, откат SQL вместе с файлами, неопределённый ответ Sheets, совместимость старых фото и граница 04:00. Проверки PHP выполняются на реальном классе MysqlBackend с изолированным адаптером SQLite; они не подключаются к рабочей базе и не проверяют конкуренцию InnoDB. Браузерные сценарии проходят через настоящий PHP gateway и тестовый Google backend.

Сборка: `npm run build:hosting`. Проверки: `npm test`, `npm run typecheck`, `npm run lint`, `npm run test:hosting` (для PHP-тестов задайте `ESCAPE_PHP_BIN` с PHP 8.3+ и SQLite3).
