# Обновление Google backend: активность и справочник

Обновляется существующая Google Sheets, без пересоздания и удаления данных. Supabase и Drizzle не нужны.

1. В Google Sheets создайте резервную копию текущей таблицы через «Файл → Создать копию» и оставьте её закрытой. Сохраните текущую версию Apps Script для восстановления кода.
2. Выполните `npm run build`. Скопируйте новые `google/dist/Code.js` и `google/dist/appsscript.json` в существующий Apps Script проект. Сохраните значения Script Properties; bootstrap повторно включать не нужно.
3. На время обновления приостановите ввод новых выполнений. Старый опубликованный код ожидает старые заголовки и после миграции временно отклонит запросы до публикации новой версии.
4. В редакторе запустите `setupDatabase`. Функция берёт ScriptLock, проверяет все заголовки, добавляет новые колонки одним атомарным запросом, затем идемпотентно добавляет 10 типов. Повторный запуск завершает прерванный seed без дублей. Незнакомые заголовки требуют проверки, функция не пытается угадывать их смысл.
5. Проверьте листы: station_task_completions и refrigerator_task_completions получили completed_by_user_id; additional_tasks — completed_by_user_id и title_snapshot; additional_task_types — is_active. Старые авторы пустые, прежние фото, ID, роли и даты сохранены. Старые названия назначений заполнены по имеющемуся справочнику, типы активны.
6. Apps Script: Deploy → Manage deployments → Edit → New version → Deploy. Сохраните прежний /exec URL.
7. Опубликуйте новую сборку Next.js с теми же переменными окружения. Вход и текущие аккаунты остаются прежними.
8. Проверьте создание и редактирование аккаунта с ролью «Аудит», просмотр активности тремя разрешёнными ролями и отказ повару; изменение/скрытие типа; выполнение с фото и фактическим автором; неизменность старого названия назначения. Дождитесь штатного снимка после 04:00 МСК и проверьте его.

Ручной reset, удаление листов и повторный bootstrap не нужны. Если нужна отмена обновления, сначала остановите запись и согласуйте восстановление кода и таблицы из копии вместе; восстановление одной таблицы после новых выполнений потеряет эти новые записи. Автоматического удаления или отката данных в скрипте нет.

Атомарность batchUpdate описана в [документации Google Sheets](https://developers.google.com/workspace/sheets/api/guides/batch). Схемы до/после и повторный запуск проверяются локальными тестами, в том числе исполнением собранного Apps Script с имитацией ошибки записи. Фактическую миграцию в аккаунте Google нужно выполнить по этим шагам: облачные идентификаторы пока не предоставлены.

Обновление удаления аккаунтов также добавляет nullable `deleted_at` в лист users. Выполните тот же `setupDatabase` и опубликуйте новую версию Apps Script/Next. Старые аккаунты получают пустое поле и остаются действующими.
