# Структура Google Sheets

Одна таблица содержит 15 листов. Исчерпывающая схема колонок и TypeScript-типы: `google/src/schema.ts`. Первая строка — заголовки; изменять их вручную нельзя. Пустые nullable значения читаются как null. Идентификаторы и даты хранятся строками, счётчики числами, признаки boolean. Строки записываются как literal stringValue, а не формулы.

| Лист | Содержание и связи |
| --- | --- |
| stations | ID и название станции |
| users | Имя, уникальный логин, scrypt-хеш, роль, nullable active_station_id → stations |
| station_tasks | station_id → stations, название, main/individual, порядок, активность, даты создания/деактивации |
| station_task_completions | task_id → station_tasks, рабочая дата, ссылки на фото Drive, время выполнения, nullable completed_by_user_id → users |
| refrigerators | Номер холодильника, station_id → stations |
| refrigerator_tasks | refrigerator_id → refrigerators, название, порядок |
| refrigerator_task_completions | task_id → refrigerator_tasks, дата, фото, время, nullable completed_by_user_id → users |
| additional_task_types | ID, название и is_active; 10 стартовых значений |
| additional_tasks | task_type_id → additional_task_types, дата, nullable фото и время выполнения, completed_by_user_id → users, title_snapshot |
| additional_task_assignees | additional_task_id → additional_tasks, user_id → users |
| daily_statistics | Итоги завершённых/всех задач по рабочей дате |
| daily_station_statistics | Итоги по рабочей дате и station_id |
| sessions | Хеш токена, user_id, истечение |
| login_attempts | Хеш ключа попыток, счётчик, время сброса |
| operations | Ключ идемпотентности, отпечаток запроса, JSON результата, истечение |

Последние три листа технические. Роль audit повторяет права chef; активность доступна обеим ролям и sous_chef. Связи, уникальность и права проверяет backend; прямое редактирование данных может нарушить эти гарантии. Доступ к таблице и папке Drive — только доверенным администраторам.

Станционные задачи и задачи холодильников имеют общее выполнение на дату; дополнительное задание — общий результат для назначенных исполнителей. Рабочая дата определяется в Europe/Moscow с границей в 04:00. Ночные выполнения до 04:00 принадлежат предыдущему рабочему дню. Снимок предыдущего дня создаётся после 04:00, повтор не меняет сохранённые итоги. Если ежедневный запуск пропущен, при открытии статистики недостающие закрытые дни восстанавливаются из истории заданий и выполнений под блокировкой; период ограничен 32 днями и первой известной рабочей датой. Удаляются только снимки старше текущей даты минус 32 дня. Фото и выполнения этой очисткой не удаляются.

Начальная загрузка создаёт 9 станций, 31 станционную задачу, 32 холодильника и 96 задач холодильников. setupDatabase не перезаписывает существующие данные. Завершение с фото компенсирует ошибку сохранения удалением нового файла, когда подтверждено отсутствие записи. Sheets и Drive не имеют общей транзакции: при неопределённом результате файл сохраняется для сверки.

Текущий адаптер читает все листы и атомарно перезаписывает изменённые листы. Нужна проверка квот и задержек на реальном объёме перед эксплуатацией. Исторические production-данные Supabase не переносились: источник не предоставлен.

Миграция: `google/src/migration.ts`. У старых выполнений автор null; у новых обязателен фактический пользователь сессии. Инструкция — `docs/GOOGLE_UPDATE.md`. Активность считается по completed_at в границах календарной недели МСК; назначенные пользователи не умножают число выполнений.

users.deleted_at — nullable ISO-время мягкого удаления. Удалённые аккаунты не входят в текущие списки, вход и назначения; строка сохраняется для ссылок исторических выполнений.


`photo_path` хранит один ID/`local:<uuid>.webp` для одного фото или JSON-массив из 2–4 таких ссылок. Старые записи читаются без изменений, листы Sheets сохраняют прежние заголовки. Для действующего MySQL поле VARCHAR(255) вмещает четыре локальные ссылки (201 символ), поэтому обновление не требует изменения таблиц. В схеме новых установок используется TEXT, а импорт допускает до 1024 символов, чтобы вместить также несколько длинных Drive ID. Число фотографий не увеличивает число выполнений, дневную статистику или недельную активность. Ошибка сохранения до попытки COMMIT откатывает выполнение и удаляет все новые файлы; при неопределённом результате COMMIT файлы сохраняются для восстановления.
