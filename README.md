# ESCAPE Restaurant Checklist

> **Для работодателя.** Это мой проект: рабочее приложение для кухни ресторана ESCAPE, которым пользуются повара и су-шефы.
>
> Сайт: **https://escapeworkspaceru.ru**
>
> Стек: Next.js (App Router), React, TypeScript, Tailwind; backend на Google Apps Script + Google Sheets + Google Drive, на хостинге PHP-шлюз и MySQL; десктоп-обёртка на Electron; тесты на Vitest и Playwright.

Внутреннее mobile-first приложение кухни: общий чек-лист станции, 9 фиксированных станций, 32 холодильника, обязательные фотографии, дополнительные задачи и статистика. Интерфейс на русском, роли **Повар / Су-шеф / Шеф-повар / Аудит**.

Backend и хранение перенесены на **Google Apps Script + Google Sheets + закрытый Google Drive**. Next.js App Router / React / TypeScript / Tailwind / shadcn/ui / Lucide сохранены. В runtime и зависимостях больше нет Supabase, PostgreSQL и Drizzle.

**Начать:** [пошаговая настройка Google и публикация](SETUP_GUIDE.md). Контракт: [API](docs/API.md), [структура Sheets](docs/DATABASE.md), [отчёт миграции](IMPLEMENTATION_REPORT.md).

## Что изменилось в сценариях

Су-шеф создаёт и редактирует аккаунты с выбором роли **Повар**, **Су-шеф**, **Шеф-повар** или **Аудит**. Аудит и шеф-повар имеют одинаковые права просмотра. Изменение роли отзывает сессии и закрывает активную станцию; последнего су-шефа нельзя лишить управляющей роли.

«Статистика активности» доступна су-шефу, шеф-повару и аудиту. Это сводка по уровням и список пользователей по имени, без рейтинга и персонального журнала задач. Неделя — понедельник 04:00 до следующего понедельника 04:00 в Europe/Moscow. 0–10 выполнений — низкая, 11–17 — средняя, 18+ — высокая активность. Учитываются фактические выполнения основных/индивидуальных задач станции, холодильников и дополнительных задач. Один общий completion даёт +1 только реальному исполнителю. В списке и сводке учитываются только аккаунты поваров; повара без выполнений показаны с низкой активностью.

«Фотографии» доступны су-шефу, шеф-повару и аудиту. «Архив фотографий» открывает календарь на 32 завершённых рабочих дня, «Сегодня» показывает текущий день. Дата определяется по `work_date` с границей 04:00 МСК. Галерея включает все снимки выполнений станционных, холодильных и дополнительных задач, даже если задача позднее скрыта. API списка проверяет роль и диапазон дат; файлы выдаются прежним приватным API с проверкой доступа к каждому выполнению. Установка на текущий MySQL-сайт описана в [PHOTO_ARCHIVE_UPDATE.md](hosting/PHOTO_ARCHIVE_UPDATE.md).

Общий checklist станции, смена через `active_station_id`, три задачи холодильника, фото, рабочий день с 04:00 МСК и 32 дня итоговой статистики сохранены. Роли admin/owner не добавляются по уточнению пользователя. Дополнительные типы можно добавлять, переименовывать и скрывать в разделе «Дополнительные задачи → Типы задач». Скрытый тип недоступен для новых назначений; название существующего назначения сохраняется в `title_snapshot`.

Стартовые типы:

1. Уборка камеры
2. Уборка морозной камеры
3. Уборка сухого склада
4. Уборка рыбного холодильника
5. Уборка мясного холодильника
6. Уборка овощного холодильника
7. Уборка пароконвектоматов
8. Уборка фритюра
9. Уборка камеры шоковой заморозки
10. Уборка лёдогенератора

Seed использует постоянные ID: повторный setup не восстанавливает прежнее название или активность изменённых типов.

## Архитектура

```text
React UI → services/api.ts → same-origin Next route handlers
                                      ↓
                        services/google-client.ts (HMAC + HTTPS)
                                      ↓
                  Apps Script: authentication / permissions / business logic
                                      ↓
                   Google Sheets (atomic batch) + private Drive
```

Next — защищённый транспорт, HttpOnly cookie, генерация случайных токенов, hashing новых паролей и проверка/перекодирование изображений Sharp. Apps Script самостоятельно проверяет сессию, роли и доступ к сущности, проверяет пароль при login, считает статистику и сохраняет данные. Компоненты не знают Google IDs и Web App URL. Пользователи не входят через Google OAuth.

Реализация Apps Script: `google/src/`. Готовая сборка для Google: `google/dist/Code.js` + `google/dist/appsscript.json`. Общие DTO: `types/models.ts`. Seed: `google/src/seed-data.ts`.

## Команды

Нужны Node **22.12+**, npm.

```sh
npm ci
npm run google:build
npm run bootstrap      # после настройки Google, через локальные env
npm run dev            # подключённый Google backend, localhost:3000
npm run typecheck
npm run lint
npm test
npm run build          # Apps Script bundle + production Next
npm start
```

Для локального просмотра без подключения облака:

```sh
npm run build
npm run preview
```

Предпросмотр на `http://localhost:3100` использует **тот же Google business core**, но хранит данные и файлы в памяти локального адаптера. Это отдельная явная команда, не fallback production. Аккаунт су-шефа берётся из `BOOTSTRAP_SOUS_CHEF_*` в локальном `.env`. После остановки данные пропадают. Начальная загрузка содержит 10 утверждённых типов. Чтобы открыть отдельный просмотр и сохранить уже работающий процесс: `ESCAPE_PREVIEW_PORT=3102 ESCAPE_PREVIEW_API_PORT=54333 npm run preview`.

E2E: `npx playwright install chromium`, затем `npm run build && npm run test:e2e`. Тесты используют изолированный adapter на 54331 и production Next на 3101; реальный Google аккаунт не нужен. Проверка настоящего Apps Script/Drive выполняется после deployment.

## Конфигурация

В локальном `.env` / серверном хостинге:

```env
GOOGLE_API_URL=
GOOGLE_API_SECRET=
CRON_SECRET=
BOOTSTRAP_SOUS_CHEF_NAME=
BOOTSTRAP_SOUS_CHEF_LOGIN=
BOOTSTRAP_SOUS_CHEF_PASSWORD=
```

Первые три нужны работающему серверу; bootstrap-переменные — только для первого аккаунта или локального просмотра. Пароли и ключи не коммитятся; `.env.example` пустой. Локальные данные Артема сохранены в `.env`. После облачного bootstrap удалите оттуда его временный пароль.

Script Properties: `SPREADSHEET_ID`, `PHOTO_FOLDER_ID`, `GOOGLE_API_SECRET`, временно `BOOTSTRAP_ENABLED=true`. Секрет одинаковый с Next; секреты и Google IDs не попадают в браузер. `AUTH_SECRET`, `DATABASE_URL`, `SUPABASE_*` больше не используются.

## Сессии, фото и конкурентная работа

Случайный session token 256 bit хранится только в HttpOnly cookie; в Sheets — SHA-256 от token. Сессия действует 7 дней. Пароли — scrypt с солью (проверка на Apps Script pure JS, совместимая с Node scrypt). Logout удаляет сессию; смена пароля аккаунта отзывает его сессии. Попытки входа ограничены 10 за 15 минут на логин.

К одному выполнению прикрепляется от 1 до 4 фотографий. Браузер сжимает каждый снимок до 1600 px, WebP 70% / JPEG fallback и показывает preview. Next проверяет размер/MIME/реальное декодирование и повторно кодирует WebP. Apps Script дополнительно проверяет magic bytes, размер и размеры WebP и сохраняет только результат в закрытую папку Drive. В Sheets — `photo_path` с одним Drive file ID или JSON-массивом из нескольких ID; base64 используется только при передаче. Оригинал и публичные Drive ссылки не сохраняются. Выдача фото идёт через проверяемый API с `private, no-store`.

Критические изменения защищены Apps Script `LockService`. Completion, assignments, idempotency ledger и snapshots записываются одним атомарным `Sheets.Spreadsheets.batchUpdate`. Повторный completion проверяется по task/date под lock. Idempotency-Key защищает повторные create/save запросы. При ошибке Drive completion не появляется; после ошибки Sheets файл удаляется только когда проверено, что на него нет ссылки. При недоступности повторной проверки файл сохраняется для последующего разбора в логах, чтобы не удалить успешно записанное фото.

## Время и расписание

Новый `work_date` — в 04:00 **Europe/Moscow**. Выполнения с полуночи до 03:59:59 относятся к предыдущей рабочей дате; задания и фото остаются доступны до 04:00. Активная станция повара при этом не сбрасывается. Технические даты активности задачи защищают вчерашний набор от добавлений/удалений после смены рабочего дня в 04:00.

Фиксацию предыдущего дня в **04:00 МСК** вызывает Google Cloud Scheduler: POST `/api/cron`, Bearer `CRON_SECRET`. Next подписывает команду для Apps Script; статистика считается и сохраняется в Google. Рекомендуемый schedule `0 4 * * *`, timezone `Europe/Moscow`. Native Apps Script time triggers не используются для точного расписания из-за временного разброса. Как и другие облачные jobs, Scheduler может задержать фактическую доставку; snapshot идемпотентен и фиксирует только закрытые рабочие даты. Повторный запуск до 04:00 не фиксирует ещё открытый рабочий день.

В snapshot входят задачи станции + холодильники; дополнительные задачи входят один раз только в общий итог. Старые snapshots не пересчитываются. Очищаются даты строго раньше today−32. Неделя — 7 дней, месяц — 30, включая сегодня. Если cron пропущен, snapshot или открытие статистики сохраняет недостающие закрытые дни за последние 32 дня по исходным заданиям и выполнениям. Даты раньше первой известной задачи/выполнения не создаются. Чтение статистики, которое может сохранить итог, выполняется под блокировкой; в замороженной Google-базе восстановление отключено.

## Ограничения и проверка production

Google credentials/deployment URL пока отсутствуют. Код и локальные тесты готовы к настройке; это не утверждение, что облачный backend уже опубликован. Известна только временная тестовая база; production Supabase не подключался и реальные данные оттуда не переносились.

Apps Script и Sheets имеют квоты/ограничения времени. Чтение таблиц пакетное, запросы страниц агрегированы и переиспользуются в рамках render; polling раз в 15 секунд только на видимой вкладке. Для большого количества одновременно открытых экранов и многолетнего объёма completion необходимо измерить нагрузку и квоты в вашем Google аккаунте. Сжатые фото передаются через Apps Script как base64, поэтому облачная выдача может быть медленнее прямого Storage.

Google Spreadsheet и Drive folder должны быть закрыты, редакторами — только доверенные владельцы. Ручные изменения строк обходят бизнес-проверки приложения; не используйте Sheet как параллельный пользовательский интерфейс.

Логотип включён без изменений: `public/images/escape-restaurant-logo.png`.

## Роль «Аудит»

`audit` — отдельная роль с теми же правами и экранами, что `chef`: просмотр результатов, фото и статистики без управления и выполнения задач. Су-шеф выбирает «Аудит» при создании или редактировании аккаунта. Существующая роль шеф-повара сохранена. Роль хранится строкой; новые поля активности и справочника добавляет миграция Sheets. Для Google нужно опубликовать новую версию Apps Script и обновить Next.js.

## Обновление существующей Google таблицы

Инструкция: [миграция активности и справочника](docs/GOOGLE_UPDATE.md). `setupDatabase` распознаёт предыдущие точные заголовки, добавляет поля без удаления строк и сохраняет их одним batchUpdate. Старые авторы остаются null. Повтор безопасен. Код миграции — `google/src/migration.ts` и `google/src/sheets.ts`; SQL, Drizzle и Supabase не используются.

`completed_by_user_id` добавлен в оба листа completions и в `additional_tasks`; `is_active` — в `additional_task_types`; `title_snapshot` — в `additional_tasks`. Новые авторы определяются только сессией на Apps Script. Недельный расчёт `google/src/activity.ts` читает нужные листы, собирает счётчики за один проход в Map и возвращает клиенту только уровни. Google Sheets не поддерживает SQL-индексы: на накопленном объёме нужен замер квот/задержки, а не фиктивные индексы. Исторические строки без автора не участвуют в активности.

Архитектура остаётся простой и допускает дальнейшее развитие. Новые функции добавляются по согласованным требованиям.

Удаление аккаунтов: су-шеф удаляет аккаунт через подтверждение в разделе «Пользователи». Аккаунт помечается deleted_at, теряет сессии и активную станцию, скрывается из списков и активности; новые задания ему не назначаются. История выполнений, авторство и фотографии сохраняются. Последнего су-шефа удалить нельзя.
